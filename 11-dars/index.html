Pul summasi va sana:
• 0.1 + 0.1 + 0.1 == 0.30000000000000004 → Pulni REAL emas, eng kichik birlikda INTEGER saqlang.
• Sanani TEXT sifatida 2026-03-15 (yil-oy-kun) yozing — matncha saralash ham to‘g‘ri ishlaydi.
Python • NULL ≠ 0 ≠ '' ekanini sinash 
import sqlite3

ulanish = sqlite3.connect(":memory:")
for ifoda in ["NULL", "0", "''", "NULL = NULL", "NULL IS NULL"]:
    q = ulanish.execute(f"SELECT {ifoda}").fetchone()[0]
    print(f"{ifoda:<13} -> {q!r}")
ulanish.close()
Natija
NULL -> None 0 -> 0 '' -> '' NULL = NULL -> None # Rost emas! Noma'lum = Noma'lum NULL IS NULL -> 1 # To'g'ri tekshirish usuli!

Ma’lumotlar yaxlitligi (Data Integrity)

Ma’lumotlar yaxlitligi — bazadagi ma’lumotlarning to‘g‘ri, to‘liq va o‘zaro muvofiq bo‘lishi. Qoidalar sxemada bir marta yoziladi va MBBT ularni har bir yozuv uchun avtomatik tekshiradi.

1-tur

Obyekt yaxlitligi

Har bir satr jadvalda noyob va aniq identifikatsiyalanadi.

Vosita: PRIMARY KEY
2-tur

Havola yaxlitligi

Referential Integrity

Boshqa jadvalga havola faqat mavjud yozuvga ko‘rsatishi shart.

Vosita: FOREIGN KEY
3-tur

Ustun qiymatlari ruxsat etilgan tur va chegaraga mos bo‘ladi.

Birlamchi kalit (PK), nomzod va tarkibiy kalitlar

Birlamchi kalitga 2 talab

  • Noyoblik: ikki satrda bir xil kalit bo‘lmaydi.
  • Majburiylik: qiymati NULL bo‘lmaydi.

Hayotiy misollar: JShShIR, STIR, talaba ID, davlat raqami.

Nomzod va muqobil kalitlar

xodimlar jadvalida xodim_id, jshshir va pasport — barchasi nomzod kalit. Bittasi PK bo‘lib tanlanadi, qolganlari muqobil (alternativ) kalit bo‘ladi.

SQL • Tarkibiy (kompozit) kalit 
CREATE TABLE baholar (
    talaba_id INTEGER,
    fan_id    INTEGER,
    baho      INTEGER,
    PRIMARY KEY (talaba_id, fan_id)
);
Python • PK takrorlanishini rad etadi 
import sqlite3

ulanish = sqlite3.connect(":memory:")
ulanish.execute("""
    CREATE TABLE mijozlar (
        mijoz_id INTEGER PRIMARY KEY,
        familiya TEXT
    )
""")
ulanish.execute("INSERT INTO mijozlar VALUES (1, 'Karimov')")

try:
    ulanish.execute(
        "INSERT INTO mijozlar VALUES (1, 'Azizova')"
    )
except sqlite3.IntegrityError as xatolik:
    print("Rad etildi:", xatolik)
ulanish.close()
Natija
Rad etildi: UNIQUE constraint failed: mijozlar.mijoz_id

Tabiiy (Natural) vs Surrogat (Surrogate) kalit

Jihat Tabiiy kalit (masalan, STIR, pasport) Surrogat kalit (masalan, mijoz_id = 17)

import sqlite3

u = sqlite3.connect(":memory:")
u.execute("""CREATE TABLE mijozlar (
    mijoz_id INTEGER PRIMARY KEY, stir TEXT UNIQUE, nomi TEXT)""")
k = u.execute(
    "INSERT INTO mijozlar (stir, nomi) VALUES (?, ?)",

Cheklovlar: NOT NULL, UNIQUE, CHECK, DEFAULT

CheklovVazifasi
NOT NULLBo‘sh (NULL) bo‘lishini taqiqlaydi
UNIQUEUstunda qiymat takrorlanishini taqiqlaydi
CHECK (...)Mantiqiy shart bajarilishini tekshiradi
DEFAULTQiymat berilmasa standart qiymat yozadi

Har ustun uchun 5 savol

  1. Majburiymi? → NOT NULL
  2. Takrorlanmasligi kerakmi? → UNIQUE / PK
  3. Chegarasi bormi? → CHECK
  4. Standart qiymati bormi? → DEFAULT
  5. Boshqa jadvalga bog‘liqmi? → REFERENCES
SQL • Jadval va ustun cheklovlari 
CREATE TABLE shartnomalar (
    shartnoma_id INTEGER PRIMARY KEY,
    raqam  TEXT    NOT NULL UNIQUE,
    summa  INTEGER NOT NULL CHECK (summa > 0),
    holat  TEXT    NOT NULL DEFAULT 'faol'
           CHECK (holat IN ('faol', 'yakunlangan', 'bekor'))
);

-- Jadval darajasidagi cheklov (2 ustun bog'liq):
-- UNIQUE (tur_id, raqam)
-- CHECK (kuchga_kirishi IS NULL
--        OR kuchga_kirishi >= qabul_sanasi)
Sinov natijalari
✓ ('SH-001', 500000) -> qabul (holat='faol') ✗ ('SH-001', 900000) -> UNIQUE constraint failed ✗ (summa=300000, raqam=NULL) -> NOT NULL constraint failed ✗ ('SH-002', -100) -> CHECK failed: summa > 0 ✗ ('SH-003', 100, 'arxiv') -> CHECK failed: holat IN (...)

“Bir-ga-ko‘p” (1:N) bog‘liqlik — eng ko‘p uchraydigan tur

Hayotiy misollar

  • 1 mijoz → ko‘p shartnoma
  • 1 bo‘lim → ko‘p xodim
  • 1 shartnoma → ko‘p to‘lov
  • 1 guruh → ko‘p talaba
Qoida: Tashqi kalit har doim “ko‘p” (N) tomondagi jadvalga qo‘shiladi. Aksincha qilish atomarlikni buzadi!

    mijoz_id INTEGER PRIMARY KEY,
    familiya TEXT NOT NULL

    shartnoma_id INTEGER PRIMARY KEY,
    raqam        TEXT NOT NULL UNIQUE,
    mijoz_id     INTEGER NOT NULL

);

“Bir-ga-bir” (1:1) bog‘liqlik

Qachon alohida jadvalga ajratiladi?

  • Maxfiylik: maosh va pasportga faqat kadrlar bo‘limi kirishi kerak.
  • Kam to‘ldirilish: faqat yuridik shaxslarda bo‘ladigan bank rekvizitlari.
  • Juda ko‘p ustun: mantiqiy guruhlarga bo‘lish qulayligi.
Qoida: Ikkinchi jadvaldagi FK ga UNIQUE qo‘yiladi (yoki FK ning o‘zi PRIMARY KEY qilinadi). UNIQUE bo‘lmasa, 1:N bo‘lib qoladi!
SQL • 1:1 (PK = FK usuli) 
CREATE TABLE xodimlar (
    xodim_id INTEGER PRIMARY KEY,
    familiya TEXT NOT NULL,
    lavozim  TEXT NOT NULL
);

CREATE TABLE xodim_maxfiy (
    xodim_id INTEGER PRIMARY KEY
             REFERENCES xodimlar(xodim_id),
    pasport  TEXT NOT NULL UNIQUE,
    maosh    INTEGER NOT NULL CHECK (maosh > 0)
);
1-xodimga 2-maxfiy yozuv kiritilsa
✓ (1, 'AA1234567', 9000000) -> qo‘shildi ✗ (1, 'AB7654321', 9500000) -> UNIQUE constraint failed: xodim_maxfiy.xodim_id

“Ko‘p-ga-ko‘p” (N:M) bog‘liqlik va oraliq jadval

SQL • Oraliq (junction) jadval 
CREATE TABLE shartnoma_advokat (
    shartnoma_id INTEGER NOT NULL
                 REFERENCES shartnomalar(shartnoma_id),
    advokat_id   INTEGER NOT NULL
                 REFERENCES advokatlar(advokat_id),
    rol          TEXT NOT NULL DEFAULT 'yordamchi'
                 CHECK (rol IN ('asosiy', 'yordamchi')),
    PRIMARY KEY (shartnoma_id, advokat_id)

4-bob • 4.6

Normallashtirish: nega hamma narsani bitta jadvalga yozmaymiz?

1. Qo‘shish anomaliyasi

Yangi xizmat turini hali shartnoma tuzilmagan bo‘lsa bazaga kiritib bo‘lmaydi.

2. Yangilash anomaliyasi

Mijoz telefoni o‘zgarsa, ko‘p satrni tuzatish kerak; bittasi qolsa — zidlik!

3. O‘chirish anomaliyasi

Mijozning yagona shartnomasi o‘chirilsa, mijozning o‘zi haqidagi ma’lumot ham yo‘qoladi.

Yangilash anomaliyasi — jonli taqqoslash 
# 1-usul (bitta jadval): faqat 1-satr tuzatildi -> zidlik!
jadval = [{"raqam": "SH-001", "tel": "+998901112233"},
          {"raqam": "SH-003", "tel": "+998901112233"}]
jadval[0]["tel"] = "+998909998877"

# 2-usul (3NF, alohida jadval): faqat 1 joyda o'zgaradi
mijoz = {1: "+998901112233"}

SQLite’da dinamik turlash, tur yaqinligi va STRICT

Dinamik turlash (Python’ga o‘xshash)

SQLite’da tur ustunga emas, har bir qiymatga tegishli (5 saqlash sinfi: NULL, INTEGER, REAL, TEXT, BLOB). Ustun turi — bu faqat tur yaqinligi (tavsiya).

Sinov natijasi

Tranzaksiyalar (ACID) va SQLite’ni qachon tanlash kerak?

A — Atomicity

Yo hammasi, yo hech narsa. Pul yechilib, ikkinchi hisobga tushmay qolmaydi.

C — Consistency

Muvofiqlik. Barcha CHECK va cheklovlar (qoldiq ≥ 0) har doim saqlanadi.

I — Isolation

Izolyatsiya. Boshqa foydalanuvchi “yarim bajarilgan” o‘tkazmani ko‘rmaydi.

D — Durability

Barqarorlik. COMMIT dan so‘ng elektr uzilsa ham o‘zgarish yo‘qolmaydi (tiklash jurnali orqali).

SQLite ideal bo‘lgan holatlar

  • Mobil (Android/iOS) va desktop ilovalar
  • CSV/Excel ma’lumotlarini lokal SQL tahlil qilish
  • Ilova fayl formati, o‘quv loyihalari, prototiplar
  • Kichik va o‘rta veb-saytlar (100 minggacha murojaat/kun)

Mijoz-server (PostgreSQL) afzal holatlar

  • Ko‘p foydalanuvchi bir vaqtda ko‘p yozadigan tizimlar (yirik bank)
  • Bir nechta serverdan tarmoq orqali ulanish kerak bo‘lsa
  • MBBT darajasida murakkab rollar va huquqlar tizimi
Boshqaruv buyruqlari: BEGIN (boshlash) • COMMIT (tasdiqlash) • ROLLBACK (bekor qilish). SQL tili bir xil — SQLite’dagi bilim PostgreSQL’da ham ishlaydi!

Python • Xavfsiz ulanish funksiyasi 
import sqlite3

def ulanish_ochish(fayl):
    """Tashqi kalitlar yoqilgan ulanish qaytaradi."""
    ulanish = sqlite3.connect(fayl)
    ulanish.execute("PRAGMA foreign_keys = ON")
    return ulanish

            7-bob • Yakun
            
Yakuniy nazorat savollari (Javob uchun savolni bosing)

          

          
        


        

          

            

              
1. CSV faylga nisbatan relyatsion MB ning afzalliklari?▾

              
Takrorlanish va zidlik yo‘q, avtomatik yaxlitlik tekshiruvi, tezkor B-daraxt qidiruvi, tranzaksiyalar (ACID) va ko‘p foydalanuvchili himoya.

            

            

              
2. Jadval, satr, ustun, domen va sxema farqi?▾

              
Jadval = obyektlar majmuasi, satr = 1 obyekt, ustun = xususiyat, domen = ruxsat etilgan qiymatlar to‘plami, sxema = jadval tuzilmasi/qolipi.

            

            

              
3. PK va FK qaysi yaxlitlik turlarini ta’minlaydi?▾

              
Birlamchi kalit (PK) — obyekt yaxlitligini; tashqi kalit (FK) — havola yaxlitligini; cheklovlar esa domen yaxlitligini ta’minlaydi.

            

            

              
4. 1:N va N:M bog‘liqliklar qanday amalga oshiriladi?▾

              
1:N — “ko‘p” tomondagi jadvalga FK qo‘shiladi; N:M — ikkala jadvalga havola qiluvchi 3-jadval (oraliq jadval) yaratiladi.

            

            

              
5. 1NF, 2NF va 3NF ning qisqa talablari?▾

              
1NF — atomar kataklar; 2NF — tarkibiy kalitning barcha qismiga bog‘liqlik; 3NF — kalit bo‘lmagan ustunlar orasida tranzitiv bog‘liqlik yo‘q.
